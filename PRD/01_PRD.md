## 1. 제품 개요

### 한 줄 요약
화물 운송 오더(상차지 → 하차지)를 등록하면 네이버 지도에서 경로·거리·소요시간을 계산하고, 조건에 맞는 차량을 추천해 배차한 뒤, 운송 중인 차량의 위치·ETA를 네이버 지도 위에서 실시간 관제하는 웹 TMS.

### 해결하는 문제
- 차량 위치·운송 진행 상황을 전화로 확인해야 함 → 관제 화면 부재
- 상·하차지 주소가 텍스트로만 관리되어 거리·운임 산정이 담당자 감에 의존함
- 가장 가까운 공차(빈 차량)를 찾는 데 시간이 걸리고 공차 운행(empty km)이 늘어남
- 도착 예정 시각(ETA)을 화주에게 근거 있게 안내하기 어려움

### 핵심 가치
| 가치 | 내용 |
|------|------|
| 지도 기반 관제 | 네이버 지도에 차량(상태별 색상)·상차지·하차지·경로선을 한 화면에 표시 |
| 실제 도로 경로 | NCP Directions 5 로 도로 거리·소요시간·경로 polyline 산출 (키 없으면 직선거리 × 1.3 보정으로 대체) |
| 주소 → 좌표 | NCP Geocoding, 없으면 네이버 개발자센터 지역 검색 API 로 좌표 확보 |
| 배차 추천 | 차종·톤수·가용 상태 필터 + 상차지까지 공차거리·운행 횟수 점수로 상위 3대 추천, 이유 표시. 최종 결정은 사람 |
| ETA 관제 | 운송 중 차량의 진행률·남은 거리·ETA 표시, 지연 경고 |

## 2. 사용자

| 사용자 | 상황 | 목표 |
|--------|------|------|
| 관제·배차 담당자 | 사무실 PC, 종일 관제 화면 사용 | 오더 등록 → 차량 배정 → 운송 진행·지연을 지도에서 파악 |
| 운영 관리자 | 일·주 단위 점검 | 차량 가동률, 공차거리, 정시 도착률 확인 |
| (Phase 3) 기사 | 휴대폰 웹 | 상태 보고, 위치 보고 |

### 시나리오 — 관제 담당자
1. 오더 등록 탭에서 상차지 "평택 물류센터" 검색 → 네이버 검색 결과 선택 → 좌표 자동 입력. 하차지도 같은 방식으로 입력.
2. 저장 시 시스템이 경로를 계산해 거리 182km, 소요 2시간 25분, 예상 운임을 표시.
3. 배차 탭에서 오더 선택 → 추천 차량 3대(공차거리·적재 가능·운행 횟수 이유 포함) 확인 → [배정].
4. 차량이 [상차완료] → [운송중] 으로 바뀌면 관제 지도에서 차량 아이콘이 경로를 따라 이동, ETA 표시.
5. ETA가 약속 시간보다 늦어지면 지연 배지 표시 → 화주 안내.

## 3. 핵심 기능

| 기능 | 설명 | 우선순위 |
|------|------|---------|
| 네이버 지도 관제 | 차량·상하차지 마커, 선택 오더 경로선, 정보창, 상태 필터 | P1 |
| 오더 등록 | 장소 검색(네이버) → 좌표 확정, 화주·차종·톤수·상차 희망시각·도착 약속시각 | P1 |
| 경로 계산 | Directions 5 (거리·시간·polyline), 실패 시 대체 계산 + 출처 표시 | P1 |
| 차량 관리 | 차량번호·차종·톤수·기사·연락처·현재 위치·상태 | P1 |
| 배차 추천·배정 | 필수 조건 필터 → 점수 → 상위 3대 + 이유, 배정/취소 | P1 |
| 운송 상태 흐름 | 접수 → 배차 → 상차완료 → 운송중 → 도착완료, 이력 기록 | P1 |
| 운송 시뮬레이터 | 실제 GPS 대신 경로를 따라 차량 위치를 주기적으로 이동 (교육·시연용) | P1 |
| ETA·지연 경고 | 진행률·남은 거리·ETA, 도착 약속시각 초과 예상 시 경고 | P1 |
| KPI 대시보드 | 오더 수·배차율·운송중·완료·총 운행거리·공차거리·정시율 | P2 |
| 운임 산정 | 기본료 + km 단가 × 톤급 계수 | P2 |
| 기사 모바일 보고 | 기사 웹에서 상태 버튼 + 브라우저 위치 보고 | P3 |
| 실 GPS 연동 | 차량 단말/앱 GPS 수신 API | P3 |

## 4. 사용자 흐름

```
오더 등록(장소 검색·좌표) → 경로 계산 → [접수]
  → 추천 확인 → 배정 → [배차]
  → [상차완료] → [운송중] (지도 이동·ETA) → [도착완료]
  ※ 접수·배차 단계에서만 [취소] 가능
```

### 상태 정의
| 코드 | 한글 | 다음 상태 | 차량 상태 |
|------|------|-----------|-----------|
| REQUESTED | 접수 | ASSIGNED, CANCELLED | — |
| ASSIGNED | 배차 | LOADED, CANCELLED | 배차대기(ASSIGNED) |
| LOADED | 상차완료 | IN_TRANSIT | 운행(ON_TRIP) |
| IN_TRANSIT | 운송중 | DELIVERED | 운행(ON_TRIP) |
| DELIVERED | 도착완료 | — | 공차(IDLE), 위치=하차지 |
| CANCELLED | 취소 | — | 공차(IDLE) |

- 정해진 순서 외 전이는 API 가 409 로 거부함.
- 배정 시 차량이 IDLE 이 아니거나 차종·톤수 조건 위반이면 거부함.
- 배차 시 차량은 상차지로 이동(공차 운행)한 것으로 간주하고, 상차완료 시 차량 위치를 상차지로 옮김.

## 5. 성공 기준

- [ ] 오더 1건 등록(장소 검색 포함) → 배정까지 **1분 이내**
- [ ] 관제 화면에서 차량·오더·경로가 **네이버 지도 위에** 표시됨
- [ ] 필수 조건(차종·톤수·차량 상태) 위반 배정 **0건** (API 가 차단)
- [ ] 추천 1순위 차량의 상차지 공차거리가 후보 중 최소 또는 사유 표시
- [ ] 운송중 차량이 시뮬레이터로 경로를 따라 이동하고 ETA 가 갱신됨
- [ ] NCP 키가 없어도 앱이 멈추지 않고 대체 모드(출처 표시)로 동작함
- [ ] 자동 테스트 통과 (상태 전이, 추천 필터, 거리 계산, API 흐름)

## 6. 안 만드는 것 (Out of Scope)

- 완전 자동 배차 — 추천 + 사람 확정 구조 유지
- 다중 경유지 경로 최적화(VRP) — 오더 1건 = 상차 1곳 → 하차 1곳
- 네이티브 앱, 백그라운드 GPS — 웹 범위 밖
- 화주 포털, 세금계산서, FPIS 실적신고, 결제
- 로그인/권한 — Phase 1 은 단일 담당자 로컬 실행 기준 (Phase 3 에서 검토)

## 7. 결정 사항 / 미결 사항

### 결정
- 지도 SDK: **NAVER Maps JavaScript API v3** (`oapi.map.naver.com/openapi/v3/maps.js?ncpKeyId=`)
- 주소 → 좌표: NCP Geocoding → (실패 시) 네이버 개발자센터 지역 검색 API
- 경로: NCP Directions 5 `driving` (`trafast` 옵션) → (실패 시) 대체 계산
- 스택: FastAPI + SQLite + 바닐라 JS (지도 SDK 를 iframe 없이 직접 로드하기 위함)

### 미결

- [ ] Directions 5 유료 구간 진입 시 호출량 제한 정책
