# 03. 단계별 개발 계획

## Phase 1 — 지도 관제 MVP (이번 구현 범위)
- [x] SQLite 스키마 + 샘플 데이터 (화주 5, 차량 12, 오더 14, 수도권·영남·호남 거점)
- [x] 네이버 API 래퍼: Geocoding / 지역 검색 / Directions 5 + 대체 계산
- [x] 오더 등록 (장소 검색 → 좌표), 경로·운임 계산
- [x] 배차 추천(필터 + 점수 + 이유) 및 배정/취소
- [x] 상태 전이 API + 이력
- [x] 운송 시뮬레이터 (경로 따라 위치 이동, ETA, 지연 경고)
- [x] 네이버 지도 관제 화면 (마커·경로·정보창·필터)
- [x] KPI 카드

완료 조건: `pytest` 통과 + 브라우저에서 오더 등록 → 배정 → 운송 → 도착 흐름 확인.

## Phase 2 — 운영 고도화
- 상차 희망시각 기반 시간창 충돌 검사, 연속 배차(도착지 → 다음 상차지) 추천
- 자연어 오더 입력 (Claude API: "내일 9시 평택→부산 5톤 윙 팔레트 10")
- 일·주 리포트 다운로드 (CSV/Excel)
- 지연 예측 알림 (ETA 가 due_at 초과 시 목록 상단 고정)

## Phase 3 — 현장 연동
- 기사 모바일 웹 (상태 버튼 + `navigator.geolocation` 위치 보고)
- 로그인/권한 (관제 / 관리자 / 기사)
- 외부 GPS 단말 수신 API (`POST /api/positions`)
- 운임 정산, 알림톡

## 시작 프롬프트 (Phase 2 예시)
```
PRD/01~04 를 읽고 Phase 2 의 "연속 배차 추천" 만 구현해줘.
조건: 기존 테스트 유지, recommend() 점수에 '이전 하차지 → 이번 상차지 거리' 반영, 이유 문구 추가.
```
